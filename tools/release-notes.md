## 这一版做了什么

一句话：**平台健康那四个按钮，现在按下去真的会做事。**

上一版它们"点了没反应"，原因在代码里：每站的「检查」实际调的是"全部检查"；「重开」只关标签页再开一个，而浏览器根本没开时它什么都做不了——重启电脑后最常见的就是这种情况。

### 0. 最要命的一条：自动巡检把按钮"锁"住了

一进「平台健康」页会自动巡检一次（只读，不打开浏览器）。这个巡检和一个给按钮用的"忙"标记共用了同一个闸——巡检没跑完时点「重开」，函数第一行就 return 了，界面上什么都不发生。你看到的就是"按了没反应"。

现在两者分开：自动巡检不再挡按钮；真有操作在跑时点了，也会提示「还在检查，等这一下完」，而不是静默。

### 1. 四个按钮各自归位

| 按钮 | 现在做什么 |
|---|---|
| 全部检查 | 先把浏览器和四个标签页准备好，再逐站探测 |
| 全部重开 | 打开浏览器 → 四站都开好 → 直接进入投递 |
| 每站 · 检查 | 只探这一站（浏览器没开就先开） |
| 每站 · 重开 | 关掉这站挂死的标签页 → 开个干净的 → 直接开跑这一站 |

### 2. 没登录不再"直接跳过"

开跑后如果某站是未登录、或者页面上有滑块，程序会把浏览器窗口提到最前，然后每 3 秒看一次：你登录完、滑块拖完，它自己继续投。

最多等 4 分钟（`config.json` 的 `LoginWaitMins`，可改成 1–15）。一轮里只会等第一次；等不到就把剩下的站跳过，不会让你白等四遍。

### 3. 仪表盘「开始投递」也是同一套

先确认浏览器、标签页、登录态，再开跑。失败原因直接写进运行日志，不再是一个"好像没动"的按钮。

### 4. 失败要快、要说清楚

浏览器起不来时，以前：白等 71 秒 → 四个站再各空转 30 秒。现在：

- **3.5 秒**内给出原因，比如"浏览器启动后马上退出了（多半是已经有一个用同一份配置打开的 Chrome 窗口，先把它完全关掉再试）"；
- 直接收尾，不再逐站重试；
- 界面上显示「浏览器没开」，不是 `nochrome` 这种内部码。

### 顺便修的两处

- 「还没登录」的提示不再让你去点已经不存在的按钮，直接说明"浏览器已打开，处理好后会自动继续"。
- 把浏览器提到最前时，只提程序自己启动的那个窗口，不会把你正在用的 Chrome 拽到前面。

### 一个解释：为什么"我自己登录了，程序还说连不上"

程序用的是**自己的一份浏览器配置**（`browser-profile\`）+ 固定调试端口 9333，跟你平时那个 Chrome 不是同一个进程、也不是同一份 cookie。所以你在日常浏览器里的登录态它看不见。

点一次「重开」（或「全部重开」），它会把**它自己那个窗口**打开并放到最前，你在那里扫码登录一次，以后就都记得了。

## 下载

`AutoApply-1.8.7-win-x64.zip`：解压到任意目录，双击 `AutoApply.exe` 即用。单文件、免安装、不用另装 .NET 或 Node。

数据在 `data\` 里（便携模式由 `AutoApply.data` 标记文件决定；没有标记则用 `%LOCALAPPDATA%\AutoApply`），升级覆盖程序文件不会动到已有投递记录和登录态。
