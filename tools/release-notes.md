## 这一版修了什么

### 1. 浏览器不再由程序自己启动（这是端口连不上的真正原因）

程序进程是 **low 完整性级别**，Windows 对这种进程拉起 Chrome 会直接杀掉：

```
crashpad_client_win.cc:423] OpenProcess: 拒绝访问 (0x5)
crash_server failed to launch, self-terminating
→ 退出码 -2147483645 (0x80000003)
```

换成经资源管理器、经计划任务、ShellExecute 中转，全都一样。所以这一版把「谁来开浏览器」换了：

- 程序启动时，把一条启动项写进 `启动` 文件夹（`AutoApply 浏览器.cmd`），**登录 Windows 后由系统自己把「专用配置 + 调试端口 9333」的浏览器拉起来**；
- 程序只负责**连** 9333，不再负责生；连上就能用；
- 想撤销：删掉 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\AutoApply 浏览器.cmd` 即可。

如果暂时不想重启，双击程序目录里的 `启动调试浏览器.cmd` 效果一样。

### 2. 平台健康页的文案不再误导

- 浏览器连上了、但这一站还没开标签页 → 显示「还没检查这一站 · 点「检查」」，不再谎报「没连上调试端口」；
- 浏览器开着但不是程序用的那个窗口 → 「你的 Chrome 开着，但不是程序用的那个窗口」；
- 起浏览器失败时，把退出码和权限级别直接红字写在标题下面。

### 3. 「运行日志」按钮不再压在卡片上

运行中才会出现的那个按钮原来落在按钮区下沿、贴着卡片边框，现在挪到副标题行最右侧。

### 4. 顺带

- 启动时日志会记录一行 `integrity = ...`，以后判断权限问题一眼就知道；
- 健康页的自动巡检与四个按钮互不影响（v1.8.8 已修，这版继续保留）。

## 升级方式

1. 关掉正在运行的 AutoApply（托盘图标右键退出，或任务管理器结束）；
2. 解压覆盖 `AutoApply.exe`；
3. **重启一次电脑**（让新的开机自启生效），或者先双击 `启动调试浏览器.cmd`；
4. 打开 AutoApply → 平台健康 → 应看到 `CDP 端口 9333 已连接`。

第一次使用请在程序自己的浏览器窗口里登录四个平台（扫码即可），之后会记住。
