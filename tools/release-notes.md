## 这一版做了什么

一句话：**浏览器由程序自己拉起来；起不来会说清楚是哪一种原因。**

### 一、"明明开着浏览器，它说没打开"

这不是程序在装傻，但界面的说法确实误导人。

程序用的不是你现在开着的那个 Chrome，而是它自己的一份浏览器（独立配置目录 `browser-profile\` + 调试端口 9333）。你平时那个窗口没有开调试通道，程序连不上它——要控制页面就必须有通道，这一点绕不开。

现在的说法分开了：

- **你有 Chrome 开着**、但不是程序那个窗口 → 卡片显示「你的 Chrome 开着，但没开调试通道 · 点「重开」用程序自己的窗口」；
- **一个浏览器都没开** → 显示「还没打开浏览器 · 点「重开」」。

### 二、点「重开」没反应

三个原因，都修了：

1. 进入平台健康页会自动巡检一次，这个巡检和按钮共用同一个"忙"标记 —— 巡检那几秒里点任何按钮都被直接 return，界面上毫无反应。现在两者分开。
2. 每站的「检查」实际调用的是"全部检查"，看起来就像没反应。
3. 「重开」只会把标签页关掉再开一个，浏览器根本没开时它什么都做不了 —— 而重启电脑后最常见的就是这种。

现在按下去会：拉起浏览器 → 打开这一站的标签页 → 直接开跑。

而且**不再把你甩到运行日志页**：就停在健康页，副标题实时显示 `● 正在运行 · BOSS直聘 · 等待登录`，旁边多了一个「运行日志」按钮，想看再看。

### 三、Chrome 起不来时，说清楚是哪一种

以前只有一句"浏览器启动后马上退出了"，剩下全靠猜。现在：

1. 先清掉"占着这份配置目录、却没开调试端口"的旧 Chrome —— 只认命令行里带本程序配置目录的进程，**不会碰你平时那个 Chrome**；
2. 再试两次；
3. 失败时按实际情况给不同的话：

| 情况 | 提示 |
| --- | --- |
| 被系统拒绝启动 | 带退出码 + 本程序权限级别，提示"正常双击一次" |
| 把请求交给了已在跑的 Chrome 后退出 | 那个窗口没开调试口，任务栏里的 Chrome 全关掉再点 |
| 其它 | 带退出码 + Chrome 自己吐的第一条错误 |

程序每次启动都会把 `integrity = low / medium / high` 写进 `autoapply.log`。以后这类问题，看这一行就能判断是不是权限导致的。

### 四、没登录就等你，不直接跳过

某站未登录或有滑块 → 浏览器窗口提到最前，每 3 秒看一次，最多等 4 分钟（`config.json` 里 `LoginWaitMins`，1–15 可调）。你登录完或拖完滑块，它自己继续投。一轮只等第一次，等不到就跳过剩下的站，不让你白等四遍。

### 五、第一次要在它自己的窗口里登录一次

程序专用浏览器是**独立配置目录**，第一次打开时四个平台都是未登录状态。请在那个弹出的窗口里各登录一次（扫码即可），之后一直记住 —— cookie 存在 `browser-profile\` 里，不会动你平时的 Chrome。

## 升级

- 先在托盘图标上右键退出正在跑的 AutoApply（直接覆盖会因为文件被占用而失败）；
- 用新的 `AutoApply.exe` 覆盖旧的；
- 数据不受影响：都在 `data\` 目录里（`AutoApply.data` 便携标记旁边）。
